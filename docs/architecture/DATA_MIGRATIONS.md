# LingoNest 数据与迁移说明

最后更新：2026-10-29

## 1. 当前数据分层

| 层 | 保存内容 | 生命周期 |
|---|---|---|
| 手机 v3 快照 | 单词、解释、词典资料、AI 笔记、分组、复习状态、当前分组 | 手机本地，关闭 App 后仍存在 |
| 手机临时状态 | 卡片翻面、当前练习题、连接配对码 | 运行期，不属于 v3 快照 |
| 手机独立设置 | 电脑地址、自动补全开关与待办 | 独立本地记录，重开仍存在，不进入单词备份；配对码不保存 |
| 手机恢复副本 | 恢复电脑备份前的完整旧快照 | 每次恢复生成独立副本，界面只指向最新一份；清除 App 数据或卸载可能丢失 |
| 电脑 SQLite | 最新一份完整备份、revision、serverId、更新时间 | 电脑本地 `server/data/lingonest.sqlite` |
| AI 内存缓存 | 已校验的分析/推荐结果和聚合计数 | 当前后端进程；重启清空 |

## 2. v2 → v3

v3 在已有可选 AI 笔记的基础上扩展词典发音资料，不改变单词、分组和复习记录的基本含义。`version` 表示快照格式；电脑备份的 `revision` 是每次写入递增的编号，两者不是同一个概念。

| v2 内容 | v3 处理 |
|---|---|
| `cards`、`groups`、`reviews`、`selectedGroupId` | 读取单词，规范化分组和复习状态；失效的当前分组回退到默认组 |
| 单例句 `aiNote.example` | 转换为 `aiNote.examples` 数组；旧内容仍可显示 |
| 没有 `pronunciation` | 保持缺省，用户以后可查询并确认保存 |
| 已有 `pronunciation` | 校验 IPA、词性、来源和安全音频地址后保留 |

迁移顺序是：优先读取 `lingonest.v3`；没有 v3 时读取 `lingonest.v2`，规范化为 v3 并写入新键；再没有 v2 时才读取更早的 `lingonest.cards` / `lingonest.groups` 等旧键。旧键不会在迁移成功后立即删除。已有 v3 损坏时显示错误，不自动回退到较旧副本，避免用户误以为最新数据仍完整。

迁移遵循三个保护条件：

1. 数据解析和引用完整性检查通过后才写入 v3。
2. 写入失败时保留旧数据，并让界面显示存储错误，不用演示单词覆盖真实数据。
3. v2/v3 快照重复单词 ID 或不安全发音字段会被拒绝；更早的旧键有重复 ID 修复逻辑。分组和复习状态按现有迁移规则规范化，不把所有旧数据问题都描述成直接拒绝。

## 3. 电脑备份兼容

手机和电脑共享 v2/v3 快照协议。SQLite 的数据库表本身没有随 v2→v3 增加词典列；完整快照作为 JSON 存在单个备份记录中，因此版本升级由协议规范化完成。

备份写入需要匹配 `expectedRevision`，同时校验 `expectedServerId`，避免旧版本或被替换的电脑数据库遭到误覆盖。恢复是整份替换，不做字段级合并：用户确认后，手机先保存恢复前副本，再写入新快照；写入前后检查本地数据是否发生变化，失败时保留当前数据。

恢复副本使用独立键保存，`lingonest.pre-restore.latest` 指向最新副本。旧副本没有自动清理机制，但界面当前只提供最新副本恢复入口。自动补全待办在开始恢复时取消，恢复后的单词不会整库自动发送给外部服务。

SQLite 当前只有一份“最新备份”，不是历史备份库，也没有独立的词汇关系表。AI 推荐、词根说明和练习草稿不会因为生成而进入数据库；只有用户确认加入的普通单词卡会随下一次手动备份出现。

修改原单词或原解释会清除该卡已有 AI 笔记，避免旧笔记对应错误词义；修改拼写还会清除旧发音资料。AI 笔记本身可单独编辑。手机存储和 SQLite 均未做应用层加密，不能把恢复副本视为独立的异地备份。

## 4. 后续升级规则

- 新增字段必须是可选字段，或提供从旧快照到新版本的确定性转换。
- 先写解析、校验和迁移测试，再修改 UI 读取路径。
- 每次迁移都保留旧数据的可恢复路径，并在测试计划中增加“旧快照重开、保存、恢复”用例。
- 如果未来改成真正的多用户数据库，应另立架构决策；不能把当前单份 SQLite 备份描述成账号后端。
