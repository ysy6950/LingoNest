# LingoNest 3.0 云端配置与验收

> 历史方案：阶段 3 已转向电脑本地后端，见 [ADR 0004](../decisions/0004-local-backend-learning.md)。本页暂不作为当前执行清单；Supabase 邮件和数据库尚未验收。

云端项目必须由项目拥有者创建。代码无需私密密钥即可继续本地运行；没有配置时，云端页会说明暂不可用。

## 配置

1. 在自己的 Supabase 账号创建项目，保存项目 URL 和 **publishable key**。不要使用 `service_role`、secret key 或未来的 AI API Key。
2. 在项目的 SQL 编辑器中执行 [`supabase/migrations/202610070001_user_backups.sql`](../../supabase/migrations/202610070001_user_backups.sql)。它建立备份表、用户读取权限和带版本检查的写入函数。先在测试项目执行，再用于正式数据。
3. 启用邮箱 OTP 登录，并把登录邮件模板配置为显示数字验证码 `{{ .Token }}`。此版本在 App 内输入验证码，不依赖邮件链接跳转。确认邮件服务可以向测试邮箱发信。
4. 复制 [`mobile/.env.example`](../../mobile/.env.example) 为本机 `mobile/.env`，填入真实项目 URL 和 publishable key。`.env` 已被 Git 忽略；不要提交它。修改环境变量后重启 Expo 开发服务。
5. 在 `mobile/` 运行 `npm install` 和 `npx expo start`，用 Android Expo Go 打开。到“统计 → 云端备份”使用邮箱登录。

## 首次验证顺序

1. 不登录时添加一个词并完成一次复习，重启后确认本地记录仍在。
2. 用测试邮箱 A 登录，确认云端为空；点击“备份当前手机数据”并确认。记下卡片数、分组和到期时间。
3. 在另一台测试手机登录 A，确认不会自动覆盖该机现有内容；点击“从云端恢复”并确认，核对单词、分组和复习进度。不要在唯一有真实数据的设备上做覆盖测试。
4. 在第二台手机修改并备份；回到第一台手机尝试备份，旧版本应被拒绝，原有本地数据保留。
5. 用测试邮箱 B 登录，确认无法读取 A 的备份；也可在 Supabase SQL 编辑器以两个用户身份检查逐行权限。退出登录后确认本机数据仍在。
6. 断网重复备份和恢复，确认错误可见且本机数据未丢失。

## 当前边界

- 3.0 是手动备份/恢复，不会自动合并两台设备的编辑。
- 首次把 Supabase 连接到 App 后，必须进行真实账号和 Android 双设备验收；本地类型检查和打包不能证明数据库权限或邮件可用。
- 恢复前的本机副本以 `lingonest.pre-restore.<时间>` 保存在设备 AsyncStorage 中；云端页提供“恢复上次本机内容”，每次回滚也会先保存当前内容。
- 如果云端项目配置错误、邮件不可达或超过 5 MiB，现有本地学习仍可用。
- 当前 npm 依赖树审计有 28 项传递依赖告警；不要运行会强制降级 Expo 或 React Native 的 `npm audit fix --force`。上线前按兼容版本和实际影响逐项复核。
