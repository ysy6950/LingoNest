# ADR 0002：MVP 2.0 信息架构与本地复习模型

日期：2026-10-06
状态：已采纳，待 Android/Expo Go 验收

## 背景

MVP 1.0 把添加单词、单词组、卡片浏览和复习放在一个页面中。随着卡片增加，页面变得拥挤，卡片浏览和复习操作互相干扰，翻面也只是瞬间替换文字。简单的“认识/不认识”记录还不能安排下一次复习。

## 决策

### 页面分工

MVP 2.0 使用 Expo Router 提供四个底部入口：

- 添加：输入单词、解释并选择分组。
- 单词组：浏览分组和卡片资料库。
- 复习：只处理已经到期的卡片，一次一张。
- 统计：展示由本地数据计算出的学习数字。

单词组详情使用两列 `FlatList`，小卡只显示单词、截断解释和待复习状态。编辑、移动、删除和翻面进入单词卡详情页完成。复习反馈不放在资料库卡片上。

### 数据分层

单词内容和复习调度分开保存：

```text
WordCard：id、word、meaning、groupId、createdAt
ReviewState：stage、dueAt、lastReviewedAt、lastResult、reviewCount
```

`isRevealed` 只属于当前页面的临时状态，不作为长期学习记录。

### 复习规则

第一版使用可解释的固定间隔，不引入 SM-2 或 FSRS：

- 新卡立即到期。
- “记住了”：1、3、7、14、30 天逐级延长。
- “有点模糊”：下一天复习，并降低一个阶段。
- “再来一次”：10 分钟后复习，并回到起始阶段。

规则位于独立的 `reviewScheduler.ts`，页面不直接计算日期。算法函数接收明确的当前时间，方便自动测试。

### 数据迁移

旧版 `lingonest.cards` 和 `lingonest.groups` 会在首次启动时转换为 `lingonest.v2`。旧键保留为恢复副本；迁移失败时不覆盖旧数据。旧版“认识”按第一阶段成功复习迁移，旧版“不认识”立即进入待复习队列。

## 取舍

- 选择 Expo Router 是因为当前已经存在真正的多页面和返回关系；单个 `activeTab` 不再适合继续扩展。
- 选择 Zustand 是为了让四个页面共享本地数据，并把保存、迁移和业务操作集中管理。
- 选择固定间隔是为了先验证“复习间隔逐步变长”的产品假设；复杂算法留到有真实使用数据后再评估。
- 选择 `FlatList` 是为了避免卡片数量增长后一次渲染整个列表。
- 选择 React Native `Animated` 是为了在不增加额外动画依赖的情况下改善翻面反馈。

## 验收边界

自动检查不能替代手机验收。必须在 Android/Expo Go 上验证四个入口、Android 返回、翻面动画、旧数据迁移、复习时间、保存失败提示和重启持久化。完成结果记录在 `docs/testing/MVP_TEST_PLAN.md`。
