# ADR 0004：阶段 3 改为电脑本地后端

日期：2026-10-16
状态：已采纳；3.0a 已实现，后续阶段待开发和验收

## 背景

原 3.0 计划使用 Supabase 邮箱验证码和云端备份。代码已写入仓库，但真实邮件、数据库和双设备流程尚未验收。配置自定义发信服务不适合当前的学习节奏；项目拥有者选择先学习自建后端。

## 决策

- 保留手机端 Zustand + AsyncStorage 作为离线学习的数据来源，不因电脑服务不可用而影响单词和复习。
- 在 `server/` 使用 Node.js、TypeScript 和 Express 构建电脑本地 HTTP 服务。3.0a 只提供绑定 `127.0.0.1` 的 `GET /health`；后续阶段再加入 SQLite、备份接口和 Android 局域网连接。
- 备份仍采用用户主动确认的整份快照，不称为自动同步。恢复前本机留档、版本冲突检查和无效数据保护继续作为后续验收要求。
- 暂停 Supabase 邮箱登录路线。旧代码和文档先保留作历史参考；完成替代实现并通过测试后，再清理不再使用的依赖及入口。

## 取舍

电脑本地服务便于理解请求、响应、路由和数据库，但电脑关机或手机离开可访问的网络时，备份服务不可用。它是开发与学习方案，不是面向公众的云端服务。无账号的开发接口不能直接暴露到公网；手机连接、局域网限制及开发测试数据的保护须在 3.0c 前明确。

不在 3.0a 加入数据库、账号或 AI，保证每一步都有可运行结果。正式多用户发布时，需要重新设计 HTTPS、身份验证、数据隔离和部署。
