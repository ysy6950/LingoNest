# ADR 0005：局域网手动备份与安全恢复

日期：2026-10-17  
状态：已实现；用户于 2026-10-17 确认 Android 实机验收通过

## 决策

1. 继续使用手机 Zustand + AsyncStorage 离线数据，电脑 Express + SQLite 保存一份 v2 快照。操作必须主动触发，不做后台同步、自动合并或账号系统。
2. 局域网默认仅健康检查。明确设置 `LINGONEST_LAN_BACKUP=1` 后才打开数据库及备份路由；绑定指定私有 IPv4，不监听所有网络地址。每次启动生成随机临时配对码，通过请求头校验，缺失或错误返回 401；手机只在 App 运行内存保留它。
3. `GET /backup` 返回数据库标识、当前版本、时间和快照。手机先读取并展示摘要，再确认覆盖。`PUT /backup` 在一次数据库事务中比较预期版本；数据库标识也必须匹配。数据库替换或版本变化返回 409，不自动重试。SQLite 标识在重启后保持不变。
4. 恢复先再次检查电脑版本与手机快照。手机等待已有保存任务结束，再写恢复副本、指针和正式快照；成功后才更新界面。写入失败不清除当前数据。提供无需网络的“撤销上次恢复”，撤销也先保留当前副本。
5. 网络输入需要严格验证，不使用旧数据迁移逻辑来悄悄修复坏备份。手机与服务端的格式检查暂分别保留，用真实 HTTP 互通测试检验一致性；以后若格式频繁变化，再评估共享模块。

## 取舍及替代方案

- 选择整份手动备份，便于解释与回滚；逐条同步需处理删除、双向冲突和离线队列，不适合本阶段。
- 选择临时配对，避免再次依赖邮箱及新基础设施；它只适用于私人开发网络。完整账号及数据隔离、HTTPS 属于正式多用户服务的工作，不能把配对码宣传成完整登录系统。
- 配对码不写进客户端源码、Git 或持久存储。2026-10-26 起，成功配对后在当前 App 运行期间跨备份、AI、词典复用，电脑地址单独持久化；完全重开 App 或服务重启时仍需重新配对。以后可评估系统安全存储中的长期配对。
- 电脑只保留最新备份，上传确认必须说明旧版本会被覆盖；手机恢复前的副本保留在 AsyncStorage。它不是云端容灾备份，卸载/清除数据会丢失手机副本。
- HTTP 上传若已提交但响应丢失，客户端无法确定是否保存，必须提示重新读取，不能宣称失败等于电脑未写入。

## 验证边界

自动测试覆盖鉴权、SQLite 重启、旧版本与旧数据库拒绝、格式拒绝、真实 HTTP 互通、恢复各写入步骤失败及重启数据保留。Android 页面、输入、确认弹窗与真实设备重启由 [3.0d 验收清单](../testing/LOCAL_3D_TEST_PLAN.md) 验证；用户已确认通过，设备型号和逐项细节未提供。
