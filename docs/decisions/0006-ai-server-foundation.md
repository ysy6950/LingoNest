# ADR 0006：电脑本地后端承载 AI 调用

- 状态：已采纳（真实服务商联调待验收）
- 日期：2026-10-23

## 背景

4.0 要建立 AI 服务基础，同时保持手机离线学习和电脑手动备份。API Key 放在 Android 客户端会随安装包暴露；直接从手机连接供应商也会让密钥和错误处理散落在客户端。

## 决策

- 手机只请求电脑本地 Express 服务；供应商 API Key 只由电脑进程从 `server/.env` 读取。
- 使用 Node 内建 `fetch` 调用配置的 OpenAI-compatible Chat Completions URL，不新增供应商 SDK 或移动端 AI 依赖。供应商地址必须 HTTPS；仅允许本机 loopback 的 HTTP 供本地模拟测试。
- 配置项齐全度分为 `disabled`、`misconfigured`、`configured`。`configured` 不宣称上游验证成功。
- 服务端只接受单词和可选释义，限制长度、要求固定 JSON 字段，处理超时、格式错误、限流和供应商失败；返回安全错误，不转发上游错误正文。AI 失败不修改手机数据，也不影响既有添加、复习和备份路径。
- 局域网 AI 路由与备份路由共用临时配对码。健康检查专用局域网模式不开放 AI 路由。
- 4.0 只提供服务基础，不改动学习页面或自动保存 AI 内容；真实服务商需要用户选择并单独联调。

## 取舍

比起给客户端增加供应商 SDK、把 Key 放在 App 或立刻建设公网后端，本地代理成本低、能复用已有 Node 服务并适合当前单人 Android 测试。但电脑必须开机且手机和电脑在可信同一网络；HTTP 未加密，所以不公开部署或发送敏感内容。供应商间的协议细节可能不同，确认服务商后必须验证兼容性。

## 后续复核

供应商变更、需要公网/多用户、密钥轮换或计费控制时更新本 ADR；用户界面和学习效果范围记在产品路线图及对应测试计划，而不是扩写本决策。
