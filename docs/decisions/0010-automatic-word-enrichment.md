# ADR 0010：新词自动补全与设备待办

日期：2026-10-27
状态：采用；实现与自动检查完成，2026-10-27 用户确认测试通过

## 问题

用户添加单词后还需分别查询音标、词性、音频和生成 AI 笔记。确认加入的关联词也重复这些操作。需要减少步骤，同时保持离线记录、人工内容和用户对外部发送的控制。

## 决策

1. 首页提供设置入口，词典和 AI 两个独立开关默认关闭。开启前说明发送哪些内容、使用哪个服务以及自动保存；可取消授权。手动 AI 继续先预览确认，两条路径并存。
2. 普通添加与确认导入关联词共用现有添加动作。新词先保存，手机再串行处理词典与 AI 待办；不自动生成或导入更多关联词，不扫描旧库。旧词在详情页显式选择补全类别。
3. 采用手机端任务队列：每个词有独立的词典/AI 待办、处理中及失败状态，一项失败不阻断其他项。仅填缺失内容，已有字段和手动编辑优先；笔记可以离线编辑或删除。
4. 设置与未完成任务用 AsyncStorage 独立键 `lingonest.auto-enrichment.v1` 保存。已保存资料复用 v3 单词数据和备份，不升级快照，不把待办或设备偏好混入备份。地址沿用共享连接，临时配对码仍只在内存。
5. 只在 App 前台、配对有效且本地保存成功时处理。后台暂停，重开并配对后继续；失败由用户重试或重新配对后重试，禁止无限循环。词典缺少音频或词性时保留可用结果并结束此次任务。
6. 保存返回前核对原词、解释、创建时间与任务身份；编辑、删除、取消、关闭相关自动开关、切换连接和恢复备份会使旧任务失效。开始恢复即取消全部旧待办，即使恢复后来失败也不复用；恢复词不自动加入队列。
7. 复用已有词典/AI HTTP 接口和校验，后端不改动。密钥留在电脑 `.env`，不新增依赖或环境变量。取消不保证撤回已发出的服务商请求，只保证过期结果不写回；暂停/重开可能重新请求，不承诺只调用一次。

## 方案比较

| 方案 | 收益 | 代价与结论 |
|---|---|---|
| 添加时等待所有服务返回 | 实现顺序直观 | 网络慢会阻塞记录，一项失败影响添加；不采用 |
| 手机待办 + 现有本地后端 | 离线先保存，可逐项恢复，无新增基础设施 | App 关闭不能持续处理，需重开配对；本阶段采用 |
| 后端长期任务系统 | 可独立于 App 处理、集中调度 | 需任务数据库、用户身份、状态查询和部署；目前需求不足 |

## 验证与边界

- 测试覆盖开关默认关闭、只处理新词、关联词共用入口、串行请求、失败隔离、重开保留、手动覆盖保护、取消、恢复与保存失败暂停。
- 网页验证授权/取消、中央连接、添加后补全、笔记编辑/删除和小屏布局；Android 导出通过。真实 Android 后台/杀进程与服务商调用仍须按 [4.3.1 测试计划](../testing/AI_4_3_1_TEST_PLAN.md) 验收。
- 本阶段没有重试次数统计、跨词缓存、持久化配对或后台服务；这些需求若出现，再记录新决策。词根说明属于 4.3.2。
