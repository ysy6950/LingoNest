# ADR 0013：AI 缓存、并发与用量统计

日期：2026-10-28

状态：已实现，自动检查通过；用户于 2026-10-28 确认测试通过

## 问题

相同单词的分析和推荐可能被重复请求，重复付费也增加等待。自动补全、手动分析和练习可能同时调用服务商，需要限制同时处理的任务，并能查看请求和失败次数。当前是个人电脑上的单进程开发服务，不需要新的数据库或部署设施。

## 决策

1. **缓存（后端数据层）**：把已校验成功的分析、推荐暂存在电脑进程内存，24 小时后过期，共用最多 200 条空间。满时移除最久未访问的条目，过期条目在访问或查询时清理。返回副本，避免某个调用者修改后污染其他结果。
2. 缓存按任务类型、校验后的完整输入和提示词版本区分；词义不同重新生成，保留大小写以区分 `US` 与 `us`。键使用 SHA-256 摘要，但摘要不是加密；缓存正文仍含生成内容，仅存在进程内，不写日志或统计接口。修改提示词时必须同步修改 `CACHE_VERSION`。不同配置的服务实例不共享缓存，修改配置须重启。
3. **请求合并（后端请求层）**：同任务、同输入的同时请求共享一次正在进行的生成和校验。分析、推荐、练习都适用；练习生成完成后不缓存题目，下次生成仍请求服务商。
4. 最多同时进行两个不同的 AI 生成任务。缓存命中或共享在途任务不占新名额；超过上限返回安全的 `busy` 提示，不排队、不自动重试。已有 90 秒后端、120 秒手机上限和严格返回校验继续使用。失败不缓存，失败后释放任务名额。
5. **聚合统计（后端观察层）**：按分析、推荐、练习分别计请求、服务商调用、缓存命中、重复合并、生成成功/失败和忙碌拒绝，另按安全错误类别计失败。只返回计数、状态、启动时间和缓存容量；不返回单词、解释、结果、密钥、配对码或服务商配置。
6. 手机设置页手动查询用量和确认清理缓存。`GET /ai/usage`、`DELETE /ai/cache` 都沿用配对权限，并返回 `Cache-Control: no-store`；查询和清理不调用 AI。清理仅清电脑缓存，保留统计及手机数据；清理时已在途任务继续处理，但其结果不能重新填回缓存。
7. 缓存及计数在电脑服务重启后归零。无新依赖、环境变量、SQLite 表或快照版本，手机仍用 v3。AI 未配置时可查询状态和零计数，原有离线学习及备份独立可用。

## 替代方案

| 方案 | 取舍 |
|---|---|
| 进程内 `Map`（采用） | 实现小、有明确容量、重启即清；不能跨重启复用，适合当前单进程服务。 |
| SQLite 持久缓存 | 重启后仍可复用，但新增表、过期清理、版本失效和内容删除责任；等跨重启需求明确再引入。 |
| Redis（独立缓存服务） | 多进程共享方便，但增加服务安装、运行和访问控制，当前没有对应需求。 |
| 完成的练习也缓存 | 可省调用，但同一组词反复出现旧题；当前优先保留再次生成的机会。 |
| 自动重试失败 | 可能改善短暂故障，也可能在服务商已处理时重复计费；当前由用户看提示后决定。 |

## 计数与边界

- `requests` 只统计已通过输入校验、进入已配置生成流程的请求；鉴权失败、未配置、非法输入不计入。每类满足：请求 = 服务商调用 + 缓存命中 + 重复合并 + 忙碌拒绝。
- `providerRequests` 是本服务发起调用的次数，包括失败尝试，不等于服务商的计费笔数、令牌用量或金额。成功/失败按真实生成任务计，共享请求不会重复计一次服务商失败。
- 推荐只缓存 AI 候选；词典核对仍在每次接口请求时执行，避免把旧的词典失败长期固定。AI 统计不包含词典或音频请求。
- 清缓存不是取消任务，也不保证紧接着的相同请求立即重新生成：若旧任务尚在进行，仍会合并等待，完成后才可再次发起新生成。
- 并发上限限制同时处理数量，不是每小时额度或费用硬上限。没有新增自动扣费预算、持久统计、多用户隔离或公网部署能力。
- AI 内容结构合规不代表语言事实正确；用户仍可检查、编辑、删除。超时也不能保证服务商停止处理或不计费。
