# ADR 0015：局域网 HTTPS 与未来账号的数据归属

日期：2026-11-03。状态：5.1a 实施中；手机真机结果单独记录。

## 背景与选择

LingoNest 继续由一台电脑在同一局域网服务少量手机，不部署公网。现有配对码由所有设备共用，只证明持有码者可以访问接口；SQLite 的 `backup` 表只保存一份完整快照。直接加登录页会让不同人的学习记录仍可互相覆盖。

先为电脑服务提供可选 HTTPS 模式，手机新构建只连接私有 IPv4 的 HTTPS。电脑在本机生成一份项目专用 CA（签发机构）与匹配当前局域网 IP 的服务证书。CA 私钥、服务私钥和电脑数据库放在被 Git 忽略的 `server/data/`；只有 CA 公开证书进入 Android 安装包。Android 校验证书链与目标 IP，不跳过证书错误。换电脑 IP 时可用原 CA 重新签发服务证书；丢失 CA 私钥时必须重新建立信任并构建新 APK。

选择现有 Express、SQLite、Expo 和 Android 网络安全配置，不引入外部登录平台。相比在每部手机安装系统证书，随 APK 携带此电脑的公开 CA 更适合这次小规模安装测试。当前 Android 配置允许系统 CA 和项目 CA，不允许明文 HTTP；项目 CA 的私钥必须由电脑主人保护。旧版本 APK 和未启用 TLS 的电脑服务仍按历史方式运行，但新 APK 不发送明文请求。

## 数据归属契约（供 5.1b / 5.1c 实现）

1. **游客资料**：现有手机 `lingonest.v3`、自动补全设置与恢复副本继续视为这部手机的游客资料。5.1a 不移动、清空或上传它们。现有 v3 快照字段不增加用户 ID。
2. **账号身份**：后端生成稳定的 `userId`；用户名只用于登录和显示。手机用 `serverId + userId` 区分不同账号的本地词库、恢复副本和待办；切换账号先停止当前任务、等待保存，再切换内存与存储命名空间。离线状态只可使用这台设备此前已验证的当前账号资料，首次登录必须连接电脑。
3. **账号备份**：新增按 `userId` 区分的备份记录，每位用户各自有 revision。后端从验证后的会话得出 `userId`，不相信请求体中的用户编号。旧 `backup(id=1)` 留作未归属的历史备份，不自动分配给第一个注册者。
4. **认领旧数据**：用户本人在 App 中检查游客词库和目标账号资料，明确确认后复制；若目标账号已有资料，不自动合并或覆盖。电脑旧备份由电脑主人通过本机管理步骤确认归属与 `serverId/revision` 后复制到自己账号，其他账号看不到。迁入前保留游客资料和旧备份原件；任何写入失败都保持原数据与当前使用的资料不变。
5. **退出与迟到请求**：退出登录只撤销访问凭证，不删除本机词库。切账号后，旧 AI 响应、自动补全待办、练习结果或备份请求不得写入新账号；本机恢复副本也不得跨账号展示。

5.1a 只确定上述契约和传输基础。账号表、登录会话、按用户备份、手机账号界面及迁移操作在后续阶段实现并单独测试；目前共享配对码仍不能提供多用户隔离，不能给朋友共用真实备份。

## 验证与回退

- 本机 HTTPS 请求必须验证公开 CA 与目标 IP；未信任的证书、错误 IP 均应失败。生成的 Android 原生配置应包含公开 CA 且拒绝明文 HTTP。
- 安装测试包前，用旧 App 对现有手机资料进行一次电脑备份并核对时间；升级安装不得卸载或清除 App 数据。新 APK 的 Android `versionCode` 递增，安装后直接降级通常不可行；出现问题时保留原手机数据并构建修复包。
- 用户资料与旧 SQLite 备份在 5.1a 不做迁移，现有本地学习继续可用；证书或连接失败只影响电脑功能。
