## 2026-10-28：把实现边界画清楚

- **架构图（系统设计层）**：用组件和请求方向说明谁负责什么。当前 SQLite 只保存最新完整备份，不是词汇关系数据库；AI 和词典是从电脑后端分出的外部服务支路。
- **数据迁移（数据兼容层）**：把旧格式转换成新格式时，先校验、再写入，并保留旧副本。v2→v3 扩展可选词典资料，同时保留已有 AI 笔记及旧单例句转换。
- **证据边界（项目管理层）**：自动测试、用户口头确认、真实 Android 截图和服务商账单分别证明不同事情。不能用其中一种证据代替另一种。

## 2026-10-28：让相同请求少调用一次 AI

- **缓存（电脑后端数据层）**：短期保留已经校验成功的结果，同词同义再请求时直接返回。当前只放电脑运行内存，24 小时、最多 200 条；重启清空，和手机长期保存笔记、SQLite 保存备份是三件不同的事。
- **请求合并（电脑后端请求层）**：两个相同请求几乎同时到达、结果还没生成时，后来的请求等待同一个任务。这样仍只调用服务商一次；缓存处理“已经完成”，合并处理“尚未完成”。最多同时两个不同任务，超额显示忙碌，失败释放名额且不自动重试。
- **聚合计数（服务观察层）**：只统计调用、命中、合并、成功失败和安全错误类别，设置页手动查询，不显示单词、解释或密钥。实际费用仍看服务商账单，查询不会调用 AI。缓存按任务和原词义区分，不把另一个意思的解释拿来复用；练习完成后不缓存题目，避免一直给旧题。
- 替代方案是把缓存写入 SQLite，或增加 Redis 缓存服务；前者需要维护过期和版本清理，后者还要运行额外服务。当前单进程先采用有上限的内存方案，不新增依赖、配置或 v3 字段。决定见 [ADR 0013](../decisions/0013-ai-runtime-cache-and-usage.md)。
- 本轮后端 44 项、手机 87 项测试、两端类型检查、Android 导出及 320/390/1280px 模拟交互通过；真实服务商和 Android 回归待按 [4.5 测试计划](../testing/AI_4_5_TEST_PLAN.md) 验收。用户已确认上一轮随机选词测试通过，未提供的设备和逐项结果不补造。

## 2026-10-27：随机选词不用请求 AI

- **随机抽取（手机业务层）**：先筛掉拼写或解释不合规及重复拼写的词，再复制数组、随机打乱顺序并取前 5 个。只有 4 个就取 4 个，不足 4 个不开始；原单词库及排列保持不变。复用已有选项洗牌函数，无需新依赖。
- **选择与生成（界面流程）**：随机按钮只更新本轮选择，先显示摘要并允许手动调整；点击“生成练习”才把词发给电脑后端。随机来源是当前分组全部可用词，不能被搜索或列表只显示 50 项的限制缩小。
- **随机的边界**：一次不会选到重复拼写，但连续两次可能抽到同一组合；这不代表按钮失效。当前未加入按熟悉度或复习历史加权的规则。
- 用户已确认 4.4 原功能全部测试通过。当时手机端 83 项测试、类型检查和 320/390/1280px 模拟交互通过，随机操作无 AI 请求；2026-10-28 用户进一步确认随机按钮测试通过。见 [4.4 测试计划](../testing/AI_4_4_TEST_PLAN.md)。

## 2026-10-27：练习题由 AI 出语言，程序守住答案

- **职责边界（产品与后端层）**：AI 只生成带空缺的例句和讲解；它不返回选项、答案索引、分数或复习结果。后端和手机都校验固定结构，避免模型输出直接改变学习数据。
- **本地判分（移动端业务层）**：选项从本轮已选单词中生成并随机排列，目标 `cardId` 决定正确答案。这样答题规则可测试、可解释，AI 只负责自然语言内容。
- **临时练习状态（状态管理层）**：本轮题目和答案只保存在页面状态，暂不写入 v3 或复习计划。源单词被编辑、删除或恢复时，旧题目会失效并要求重新生成。
- **问题记录**：AI 生成的题目可能有语义歧义，所以提供跳过/排除入口；排除题不计分。当前只做一种题型，先收集真实质量再决定题库、缓存和复习联动。
- 验证：后端 33 项、手机 81 项自动测试、两端类型检查、Android 导出和 390px 模拟流程通过；真实服务商和 Android 实机待用户按 [4.4 测试计划](../testing/AI_4_4_TEST_PLAN.md) 回归。

## 2026-10-27：超时是停止等待，不是撤回请求

- **超时上限（网络请求层）**：本程序愿意等待一次请求多久。之前后端 15 秒就中止 AI 请求，即使手机愿意等 35 秒也拿不到成功结果；现改为后端 AI 90 秒、手机 120 秒，为后续并行词典核对和网络传输留余量。
- **请求取消的边界（外部服务层）**：本地停止等待不能保证服务商停止生成或不计次。不要把超时理解为“请求未发出”，也不要连续重新生成；本次没有加入自动重试。
- **阶段耗时（排错层）**：推荐日志分别记录 AI、词典和总时间，1000 毫秒等于 1 秒。用户观察到生僻词更容易超时，但原因也可能是排队、网络或输出长度，需要日志判断，不先认定词难就一定更慢。
- 选择延长有上限的等待；后台保存任务再取回结果能支持更长处理，但要新增任务状态与存储，本次不引入。两端类型检查及 102 项测试通过；用虚拟计时模拟慢返回和最终中止，没有真实调用服务商。手机回归步骤见 [超时修复验收](../testing/AI_4_3_2_TEST_PLAN.md#超时修复回归)。

## 2026-10-27：词根说明与真实性边界

- **构词分类（产品内容层）**：共同词根、加前后缀形成的派生词、同一词的语法变化不是同一件事。分别展示相关部分和含义，不清楚构词时允许待确认，连关联都不清楚时不推荐。
- **结构化字段（接口数据层）**：把分类、基础部分、含义、词缀分别放进固定字段，代替一整段难检查的自由文字。前后端可检查字段和长度，但无法靠这些检查证明词源真实；词典词形命中也不是词源证据。
- **向后兼容（接口与界面层）**：新手机遇到旧后端没有构词说明时给出更新提示，不猜内容。提示词运行在电脑后端，因此更新后须重启电脑服务，手机重新配对并重载。
- 采用现有 AI 的结构化说明，不新建词根数据库；授权词源数据库可提供独立证据，但还需解决许可、覆盖和维护。取舍见 [ADR 0011](../decisions/0011-word-family-explanations.md)。
- 验证：手机 73 项、后端 27 项测试、类型检查、Android 导出及多宽度网页回归通过。没有调用真实服务商；实机与构词准确性按 [4.3.2 测试计划](../testing/AI_4_3_2_TEST_PLAN.md) 核对。用户已确认上一阶段 4.3.1 测试通过。

## 2026-10-27：新词先保存，资料随后补全

- **任务队列（手机业务层）**：把未完成的词典和 AI 工作记成待办，逐项处理。它不是新的服务器或数据库；采用现有 Zustand + AsyncStorage，避免同时发起大量请求。新词保存与生成分开，电脑断网不妨碍记录单词。
- **设备设置与学习数据（存储层）**：开关、待办在手机单独保存；已经补全的内容仍在 v3 单词卡中，可备份。配对码属于访问凭证，只放运行内存，重开需重配；关闭 App 不等于后台一直运行。
- **异步结果核对（数据保护层）**：请求发出到返回之间，用户可能改词、删词、取消或恢复备份。保存前核对原词、解释、创建时间与当前任务；旧任务返回不再写入。手动编辑已有资料优先，自动补全只填缺失内容。
- **授权范围（产品层）**：默认关闭，开启前说明发送内容和自动保存；用户确认加入的关联词也补全，但不自动推荐或加入更多词。开启不扫描旧库，旧词需单独选择，避免意外整库发送。
- 选择手机端串行待办，替代方案是后端任务系统；后者需额外用户身份、任务数据库与跨设备状态，本阶段无此需求。验证通过：70 项手机测试、两端类型检查、Android 导出与 320/390/1280 网页交互；真实 Android 与服务商效果待用户验收。

## 2026-10-26：关联词从预览到正式单词卡

- **候选生成（后端 AI 层）**：把原词和当前解释交给 AI，要求返回四类词和推荐理由。单词多义，必须携带当前解释；返回数量和 JSON 格式能校验，但近反义关系是否准确仍需人工判断。
- **词形核对（外部数据层）**：后端用已有词典核对词条 ID、词头或词形列表。词典返回拼写建议不等于查到了该词；查到词形也不能证明 AI 给的关系、释义和词源正确。词典故障时必须显示尚未核对，不能假装成功。
- **确认边界（本地数据层）**：预览只是页面临时数据，取消不写入；确认才调用普通添加流程，写入 v3 卡片并安排初始复习。因此不需再升级快照或加数据库表，重开与备份复用现有实现。
- **查重规则（本地数据层）**：去掉首尾空格、把连续空白合成一个、忽略大小写，再比较整个单词库；分组不同也不能绕过推荐查重。确认时重查原词是否被修改/删除，防止把过期结果存入。
- 采用 AI + 词典词形核对，比只信 AI 多一层独立检查；导入完整词典关系库需要额外授权、词义对齐与维护，当前先不增加这部分工作。决策见 ADR 0009。

## 2026-10-26：音频地址与连接复用

- 词典 API 返回音频**文件名**，它不是完整网址；后端须依官方规则补上文件目录。音标成功只能证明查询接口正常，不代表音频文件能播放。
- 播放器会经历加载、播放、失败等状态；点击按钮后要显示状态并处理超时，不能只调用 `play()` 就假定用户听到了。
- 电脑地址是普通连接配置，可以单独记住；临时配对码是访问凭证，当前只在 App 运行内存中跨页面复用，不能写进单词备份或 Git。电脑服务重启会换码，旧配对会被 401 拒绝。

## 2026-10-24：4.2 发音、音标和数据版本

- **设备朗读（TTS）**处于手机能力层：Expo Speech 把英文词交给系统语音引擎，不等于词典真人录音；即使电脑词典不可用，朗读仍可单独尝试。
- **词典 API**处于外部数据层：手机只向已配对的电脑后端提交单词；后端用电脑环境变量里的 Key 查 IPA、校验结构，再返回少量安全字段。音标不能由用户猜写，也不让 AI 猜测代替词典。
- **快照迁移**处于本地数据层：先读 `lingonest.v2` 并转换成 v3，成功写入 `lingonest.v3` 后才让界面使用；旧键保留。读取旧电脑备份也转为 v3，保留词、组、复习和 AI 笔记。
- **真实联调与配置状态不同**：`Dictionary configuration: configured` 只代表有 Key；首次请求被拒绝，用户修正 Key 后成功取得音标。成功结果的来源标识也证明该次数据来自 Merriam-Webster API。
- **口音来源**：官方音频目录按 `en/us` 提供美式资源；不能从 Merriam-Webster 结果推断存在英式录音。现在美式按钮播放词典公开音频，英式按钮使用 Android `en-GB` 系统语音，并在界面明确标记来源。
- **公开音频地址**处于数据安全层：后端只接受词典返回的安全文件名，并拼接固定 `media.merriam-webster.com` HTTPS 路径；API Key 仍只在电脑后端，不进入手机或音频地址。没有音频的单词不会阻塞音标保存。
- **展示层调整**：本轮将 IPA 和词性作为可选属性传入卡片组件，在正面单词下展示；释义面不显示它们。类型检查、手机 41 项测试、后端 18 项测试和 320/390/1280 网页回归通过，Android 新布局和声音待确认。

## 2026-10-17：3.0c 手机与电脑的局域网连接

- **局域网 IP**（网络层）是电脑在当前 Wi-Fi 中的地址；手机上的 `localhost` 指向手机本身，不是电脑。
- **监听地址**（服务层）决定服务接受哪些网络接口的连接。默认 `127.0.0.1` 只允许电脑自己访问；显式绑定私有局域网 IP 后，手机才可能连接。
- **HTTP 健康检查**（接口层）只返回服务状态，不读取单词。局域网模式关闭 `/backup`，因为此阶段没有账号验证。
- **实际限制**：电脑和手机要在可互访的网络里；防火墙、设备隔离以及 Expo Go 的 Android HTTP 策略都可能阻止访问，必须按实机结果判断。Expo tunnel 不会自动转发本地 API。

服务端与 App 自动测试、电脑侧局域网请求通过。用户于 2026-10-17 报告 3.0c 测试通过；未提供的设备信息及逐项结果不补造，见 `docs/testing/LOCAL_3C_TEST_PLAN.md`。

## 2026-10-16：3.0b 电脑本地数据库

- **SQLite**（数据库层）把一份测试备份存进电脑上的文件；服务重启后仍能读到，与手机 AsyncStorage 是两处不同的存储。
- **接口**（服务层）新增 `GET /backup` 和 `PUT /backup`；浏览器或测试程序通过 HTTP 请求它们，手机尚未接入。
- **版本冲突**（数据保护）要求提交时带上已知版本：第一次是 `0`，成功后得到 `1`；旧版本再写入会被拒绝为 HTTP 409。
- **输入校验**（服务边界）网络传来的 JSON 不因 TypeScript 类型声明就可信，必须检查结构与大小后才写入数据库。
- **PowerShell 小问题**：若 `npm` 被执行策略拦截，可用 `npm.cmd`，无需降低系统安全设置。

本轮自动检查通过；用户仍需按 `server/README.md` 用测试数据手动验证一次写入、重启与读取。原云端邮箱方案暂停，不与本地后端混用。

## 2026-10-06：MVP 2.0 页面与复习流程

### 做了什么

- 将单页面原型重构为 Expo Router 的四个底部入口：添加、单词组、复习、统计。
- 使用 Zustand 让不同页面共享单词、单词组和复习进度；使用 AsyncStorage v2 快照保存。
- 将单词内容与复习状态分开。卡片详情的翻面只属于当前界面，不会偷偷修改复习计划。
- 单词组详情使用两列 `FlatList`，并加入搜索和“最近添加 / 字母顺序 / 待复习优先”排序。
- 复习会话在开始时固定到期卡片队列，一次处理一张，翻面后显示三档反馈和本次总结。
- 编写固定间隔规则：记住了为 1、3、7、14、30 天；有点模糊为 1 天并退一步；再来一次为 10 分钟并回到起点。
- 增加旧 AsyncStorage 数据迁移，迁移失败时保持未覆盖旧数据。

### 新概念的实际用途

- **路由**：决定当前显示哪个页面，以及 Android 返回键如何回到上一层。
- **共享状态**：让添加页保存的卡片能马上在单词组、复习和统计页看到。
- **派生数据**：待复习数量和统计从卡片与复习记录计算，避免保存两套容易冲突的数字。
- **调度规则**：把“这张卡下一次什么时候出现”作为纯函数计算，便于验证和以后替换算法。
- **迁移**：读取旧格式时转换为新格式，保留旧键作为恢复副本；不能把一次升级当成数据已经安全的证明。
