## 2026-10-17：手机手动备份与恢复

- 已做：Express 的配对读写接口、SQLite 数据库标识、手机备份页、覆盖确认、恢复前留档及离线撤销。3.0c 已由用户报告测试通过，3.0d 实机待验收。

- **恢复副本（手机存储层）**：替换当前数据前先另存旧数据，写成功才更新界面；保留撤销入口。不是卸载后还能找回的远程备份。

## 2026-10-17：3.0c 手机与电脑的局域网连接

- **局域网 IP**（网络层）是电脑在当前 Wi-Fi 中的地址；手机上的 `localhost` 指向手机本身，不是电脑。
- **监听地址**（服务层）决定服务接受哪些网络接口的连接。默认 `127.0.0.1` 只允许电脑自己访问；显式绑定私有局域网 IP 后，手机才可能连接。
- **HTTP 健康检查**（接口层）只返回服务状态，不读取单词。局域网模式关闭 `/backup`，因为此阶段没有账号验证。
- **实际限制**：电脑和手机要在可互访的网络里；防火墙、设备隔离以及 Expo Go 的 Android HTTP 策略都可能阻止访问，必须按实机结果判断。Expo tunnel 不会自动转发本地 API。

服务端与 App 自动测试、电脑侧局域网请求通过。用户于 2026-10-17 报告 3.0c 测试通过；未提供的设备信息及逐项结果不补造，见 `docs/testing/LOCAL_3C_TEST_PLAN.md`。

## 2026-10-16：3.0b 电脑本地数据库

- **SQLite**（数据库层）把一份测试备份存进电脑上的文件；服务重启后仍能读到，与手机 AsyncStorage 是两处不同的存储。
- **接口**（服务层）新增 `GET /backup` 和 `PUT /backup`；浏览器或测试程序通过 HTTP 请求它们，手机尚未接入。
- **版本冲突**（数据保护）要求提交时带上已知版本：第一次是 `0`，成功后得到 `1`；旧版本再写入会被拒绝为 HTTP 409。
- **输入校验**（服务边界）网络传来的 JSON 不因 TypeScript 类型声明就可信，必须检查结构与大小后才写入数据库。
- **PowerShell 小问题**：若 `npm` 被执行策略拦截，可用 `npm.cmd`，无需降低系统安全设置。

本轮自动检查通过；用户仍需按 `server/README.md` 用测试数据手动验证一次写入、重启与读取。原云端邮箱方案暂停，不与本地后端混用。

## 2026-10-06：MVP 2.0 页面与复习流程

### 做了什么

- 将单页面原型重构为 Expo Router 的四个底部入口：添加、单词组、复习、统计。
- 使用 Zustand 让不同页面共享单词、单词组和复习进度；使用 AsyncStorage v2 快照保存。
- 将单词内容与复习状态分开。卡片详情的翻面只属于当前界面，不会偷偷修改复习计划。
- 单词组详情使用两列 `FlatList`，并加入搜索和“最近添加 / 字母顺序 / 待复习优先”排序。
- 复习会话在开始时固定到期卡片队列，一次处理一张，翻面后显示三档反馈和本次总结。
- 编写固定间隔规则：记住了为 1、3、7、14、30 天；有点模糊为 1 天并退一步；再来一次为 10 分钟并回到起点。
- 增加旧 AsyncStorage 数据迁移，迁移失败时保持未覆盖旧数据。

### 新概念的实际用途

- **路由**：决定当前显示哪个页面，以及 Android 返回键如何回到上一层。
- **共享状态**：让添加页保存的卡片能马上在单词组、复习和统计页看到。
- **派生数据**：待复习数量和统计从卡片与复习记录计算，避免保存两套容易冲突的数字。
- **调度规则**：把“这张卡下一次什么时候出现”作为纯函数计算，便于验证和以后替换算法。
- **迁移**：读取旧格式时转换为新格式，保留旧键作为恢复副本；不能把一次升级当成数据已经安全的证明。
