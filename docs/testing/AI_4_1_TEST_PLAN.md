## 开始前

1. 在电脑后端终端按 `Ctrl+C` 停止旧服务，重新以 3.0d 的局域网配对备份模式运行 `npm.cmd start`。此前配对码已出现在聊天中，必须使用这次新生成的码。
2. 确认启动行是 `LingoNest LAN backup server: http://电脑IP:3001/health`，并显示 `AI configuration: configured`。这只说明格式齐全，不代表真实 AI 已验证。保持该终端运行，不要重复启动另一个服务。
3. 手机与电脑连接同一可信 Wi-Fi；在 `mobile/` 启动 Expo Go 项目。先在“统计 → 检查电脑连接”确认可达。

## 在手机上操作

1. 打开“单词组”中的一张单词卡，记下当前自己写的解释。向下滑到“AI 学习笔记”，点“AI 辅助”。
2. 输入电脑启动行中的 IP 和端口，例如 `192.168.5.46:3001`（不是 `http:` 前缀），输入**本次启动**显示的临时配对码。不要输入 AI API Key。
3. 点“生成预览”。这是唯一会向所配置服务商发出付费请求的动作。首次测试只用 `learn` 等不含隐私的常见词。
4. 成功时应看到英语解释、中文提示和三条例句的可编辑输入框。核对三句是否自然、是否属于原解释所指的同一词义，是否重复；此时点“取消”，原解释和已有笔记都应保持原样。
5. 再次生成，修改一条例句，删除另一条，确认剩余两条仍可保存；也可手动补回第三条。点“确认保存学习笔记”，详情页应逐条显示修改后的笔记，原解释仍保持原样。
6. 关闭并重新打开 App，确认笔记仍在；完成一次复习后确认复习流程无异常。若要验证备份，手动备份到电脑并读取，按原 3.0d 恢复保护流程操作，勿直接覆盖唯一数据副本。
7. 检查升级前已保存的单例句笔记仍可查看；读取旧电脑备份时仍能保留旧例句。恢复测试会替换手机内容，务必先留可恢复副本。尝试旧配对码、断开电脑服务及 AI 未配置场景：应有可理解错误，已有数据不应丢失。

## 保存后编辑与界面回归（本轮待 Android 确认）

1. 打开已有 AI 笔记的单词卡，确认笔记标题右侧有“编辑”和“AI 辅助”；英语解释、中文提示在带边框的释义区中，例句为独立编号条目。窄屏及系统大字体时不应互相遮挡。
2. 不连接电脑，点“编辑”。应直接显示当前笔记，不要求地址或配对码；修改解释及例句后点“取消”，已有笔记保持不变。
3. 再次编辑英语解释、中文提示、例句，尝试删除或补回，保持 1～3 句；点“保存修改”，应显示新内容。原单词、原解释、分组与复习进度保持不变。
4. 留空必填内容或输入重复例句后保存，应有错误提示且旧笔记保留；修正后可保存。关闭并重开 App，确认修改仍在。旧单例句笔记也应能编辑并补句。
5. 检查软键盘打开时可滚动到全部字段和保存/取消按钮，Android 返回键可取消编辑，不会保存半成品；再次打开编辑应读取原笔记。重新生成后取消也不应覆盖现有笔记。

## 生成预览失败时

1. `电脑IP:端口` 和配对码能用于备份，只证明手机能访问后端、通过配对；AI 还需要后端成功请求外部服务商。`AI configuration: configured` 也只证明配置字段齐全。
2. 若刚修改了代码或 `server/.env`，在旧后端窗口按 `Ctrl+C`，用原局域网配置重新运行 `npm.cmd start`，使用新生成的配对码。不要在旧进程运行时重复启动同一端口。
3. 仅用一个公开常见词重试一次，查看手机显示的具体错误，以及电脑终端 `[AI] request failed: 错误类别 (upstream HTTP 状态)`。`provider_not_found` 通常先核对 Base URL 和接口路径；`provider_auth` 核对服务商账号/Key；`provider_rejected` 核对模型名及协议兼容性；`rate_limited` 是服务商限流；`timeout` 检查网络或服务商响应时间。不要连续反复请求，以免产生费用。
4. 报告问题时只提供错误类别、HTTP 状态和复现步骤；不要提供 API Key、配对码、完整请求头或含个人内容的 AI 响应。
