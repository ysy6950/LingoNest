# 4.5 稳定性、缓存与成本控制验收

日期：2026-10-28

状态：实现及自动检查通过；用户于 2026-10-28 确认测试通过。不要把自动检查记作实机结果，不记录密钥或配对码。

## 本次范围

- 分析、推荐的成功结果在电脑内存缓存 24 小时，共享最多 200 条，区分任务、大小写及词义。
- 同输入的在途 AI 请求合并，同时最多两个不同生成任务；失败不缓存、不自动重试。
- 练习只合并同时请求，完成的题目不缓存。
- 添加页右上角“设置” → “AI 服务用量”：手动查询计数、失败类别及确认清缓存。
- 无新依赖或 `.env` 配置，v3 手机数据及 SQLite 备份格式不变。

## 准备

1. 保留现有数据，不清除 Expo Go 数据、不卸载 App。
2. 在原后端运行窗口按 `Ctrl+C`，在 `D:\Project\LingoNest\server` 运行 `npm.cmd start`。沿用之前的局域网启动环境；若换了终端，按 `server/README.md` 重新设置当前电脑 IP、`LINGONEST_LAN_BACKUP=1` 和端口后启动。
3. 手机重新加载 App，在设置中输入本次启动的新配对码并连接电脑。沿用现有 AI 配置，不分享配对码。
4. 为便于比较计数，可暂时关闭自动补全、等已有任务完成，测试后恢复原设置。每次操作后点击“查询用量”刷新；界面不会自动实时刷新。

## 手机人工验收

| 用例 | 操作 | 预期 |
|---|---|---|
| 初始用量 | 重启后进入设置查询 | 显示本次启动时间、配置状态，缓存和计数从零开始；查询本身不增加 AI 调用。 |
| 分析缓存 | 找一个普通测试词，保持原解释不变，生成预览、取消，再生成一次；每次回设置查询 | 第一次分析调用加 1，第二次缓存命中加 1、服务商调用不再增加。无需保存预览，已有笔记和原解释保持。 |
| 词义隔离 | 用测试词修改原解释，再生成 | 新词义增加一次调用，不复用旧词义的缓存；测试后可恢复解释。 |
| 推荐缓存 | 对同词同义连续生成两次推荐 | 第二次推荐缓存命中加 1；词典核对仍会执行，不能要求整个请求完全无网络等待。推荐仍逐项确认加入。 |
| 练习新生成 | 选相同 4～5 个词，完成或退出一轮后再生成 | 每轮各增加一次练习调用，练习缓存命中不增加。模型仍可能碰巧返回相似题目，不能靠文字不同判断是否调用。 |
| 清理前取消 | 用量有缓存时点击清理，再点“返回” | 没有执行清理，缓存数量不变。 |
| 确认清理 | 确认清理，再对刚才词义生成分析 | 缓存清零、已有调用统计保留；手机单词、笔记、复习和备份仍在；待旧任务完成后再次生成增加一次调用。 |
| 重启边界 | 重启电脑服务、重新配对并查询 | 统计和缓存清零；手机已保存资料不丢，电脑 SQLite 备份仍存在。 |
| 错误与离线 | 断开电脑或手机 Wi-Fi 后查询/生成，再恢复连接 | 显示可理解错误、不自动重试；手机添加、查看、编辑、复习仍可用。恢复连接后备份仍正常。 |
| 窄屏与连接变更 | 常用 Android 宽度查询、打开清理确认框、更换连接 | 文字和按钮不被遮挡，取消及确认可用，旧电脑的统计不残留。 |

补充：未配置 AI 的回归可在有需要时按 4.0 步骤临时关闭配置后重启，预期设置显示“AI 未开启”，原有添加、复习和备份正常；恢复原配置再重启。不要为了验收把真实密钥粘贴到日志。错误密钥、限流、非法返回、最终超时在本轮自动测试已覆盖，无需反复用真实账户制造失败。
