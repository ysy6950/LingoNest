# 5.1b 后端账号与权限验收

日期：2026-11-03。范围：电脑后端；手机账号界面属于 5.1c。

## 已运行的自动检查

- `server/` 执行 `npm.cmd run typecheck`、`npm.cmd test`：47 项后端测试通过。
- 临时 SQLite 中的管理员、成员邀请码均只能用一次；密码错误、旧配对码、已退出会话不能访问备份。服务重启后有效会话和每人备份仍在，已撤销会话保持失效。
- A/B 都可写入自己的合法快照，A 无法看到 B 内容；并发版本冲突、错误 `serverId` 不覆盖旧内容。请求体伪造 `userId` 不改变归属。
- 成员不能列账号或清除全局 AI 缓存；同词 AI 分析在 A/B 间不共用缓存，统计按人隔离，全局并发上限保持不变。
- 旧单份备份不随注册分配；本机认领需正确旧版本且目标为空。成功复制后旧记录仍在。

## 电脑端手动检查（账号模式正式启用前）

1. 保留现有手机 App、数据库和备份，不卸载或清空。5.1c 发布前，日常服务保持 `LINGONEST_ACCOUNTS` 未设置。
2. 若要独立试账号接口，请用临时 `LINGONEST_DB_PATH`，确认路径不指向现有 `server/data/lingonest.sqlite`，并开启 LAN IP、备份、TLS、账号四个环境变量。启动后检查 `/health` 的 `lan-accounts`。不要将邀请码、密码、会话令牌放入仓库或聊天。
3. 使用电脑本机 `accounts` 管理命令生成管理员邀请；注册 A、创建成员邀请、注册 B。检查旧配对码访问备份为 401，两人备份互不相见，退出后会话失效；密码重置后旧会话均失效。
4. 切回历史模式需停止服务，在同一 PowerShell 执行 `Remove-Item Env:LINGONEST_ACCOUNTS -ErrorAction SilentlyContinue` 后重启。旧客户端可继续按临时配对码连接；不会自动把任何账号备份复制回旧单份备份。

真机双账号、离线切换、游客资料迁入与迟到 AI 结果属于 5.1c / 5.1d；本阶段不能据后端测试宣称这些已验证。
